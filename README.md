# WPAIPlugin

## Generated Plugin Validation

Proves a plugin generated by the deterministic `PluginBuilder` can actually be
installed and activated in a real WordPress site, not just pass unit tests.

**Requires:** Docker Desktop (running), PowerShell 7+.

**Run:**

```
powershell -ExecutionPolicy Bypass -File scripts/Validate-GeneratedPlugin.ps1
```

**Expected output on success:**

```
[1/5] Starting API
[2/5] Building plugin
[3/5] Starting WordPress
[4/5] Validating plugin
[5/5] Cleaning up
PASS: Plugin installed and activated successfully.
```

**What it checks:**
- Builds and starts the existing API, POSTs a deterministic `PluginSpec`
  (exercising shortcode, custom-post-type, settings-page, custom-fields, and
  scheduled-task) to the existing `POST /api/plugins/build` endpoint
- Starts a disposable MariaDB + WordPress + WP-CLI environment via Docker Compose
- `php -l` lints every generated PHP file before anything else runs
- Installs WordPress non-interactively, then `wp plugin install` +
  `wp plugin activate` + `wp plugin is-active` against the generated ZIP
- Fails immediately, with the exact command and exit code, if any step fails

**Cleanup:** the Docker containers, network, and volume are always torn down
(`docker compose down -v --remove-orphans`) and the API process is stopped in
a `finally` block, even if validation fails — nothing is left running.

This script is a manual/CI integration check. It requires Docker and is not
part of `dotnet test`, which remains Docker-independent.
